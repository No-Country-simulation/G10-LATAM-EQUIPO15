# Data Model: AI Data Processing Pipeline

## Entities

### `PipelinePayload`
The core input structure entering the system for processing.
- **Fields**:
  - `id` (UUID): Unique identifier for the transaction.
  - `raw_text` (String): The input data to be processed. Must have `max_length` constraints to prevent buffer/context overload.
  - `metadata` (Dict): Additional contextual info (e.g., source, timestamp).
- **Validation Rules**:
  - `raw_text` must not exceed 100,000 characters.
  - Basic sanitization to strip null bytes or extreme special characters.

### `AgentOutput`
The structure capturing the generated state from the multi-agent system.
- **Fields**:
  - `agent_name` (String): Identifies which agent produced the output (e.g., "analizador", "ensamblador").
  - `content` (Dict / Pydantic Model): The structured output (like Mermaid syntax, or JSON insights).
  - `token_usage` (Integer): Track token consumption for this step.
- **State Transitions**:
  - Transferred sequentially from `analizador` -> `creador` -> `critico` -> `ensamblador`.

### `AuditReport`
The structure generated by the local Hermes 3 model analyzing the agent output.
- **Fields**:
  - `is_secure` (Boolean): Pass/Fail flag.
  - `vulnerabilities` (List[String]): Any logic flaws or injection risks detected.
  - `recommendations` (List[String]): Actionable fixes.
- **Validation Rules**:
  - Parsed strictly as JSON from Hermes.
