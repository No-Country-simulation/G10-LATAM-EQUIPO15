## User Scenarios & Testing *(mandatory)*

### User Story 1 - Process Data through AI Pipeline (Priority: P1)

As a system orchestrator, I want to process incoming data through the AI pipeline so that the data is correctly ingested, analyzed, and assembled into a final output using the established multi-agent pattern.

**Why this priority**: The core functionality of the AI system relies on successfully moving data from ingestion to the final assembled state.

**Independent Test**: Can be fully tested by submitting a sample data payload and verifying the generated output structure.

**Acceptance Scenarios**:

1. **Given** raw input data, **When** the pipeline is triggered, **Then** the data is processed sequentially by the configured agents.
2. **Given** a high volume of input, **When** the pipeline processes it, **Then** it gracefully manages latency and token usage effectively.

---

### User Story 2 - Audit Pipeline Operations with Hermes (Priority: P2)

As a security and logic reviewer, I want the pipeline's execution to be audited using local Nous Hermes 3 so that any vulnerabilities, logic flaws, or inefficiencies are flagged securely.

**Why this priority**: Security and logic auditing is crucial for robust operations without relying entirely on external API models for sensitive review tasks.

**Independent Test**: Can be tested by running the auditing process on a known flawed AI payload to ensure Hermes catches the issues.

**Acceptance Scenarios**:

1. **Given** the output from the core AI agents, **When** the auditing step runs, **Then** Hermes generates a compliance and logic audit report.
2. **Given** a payload containing an anomaly, **When** audited, **Then** Hermes flags the anomaly with high precision.

---

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: The pipeline MUST orchestrate data processing across the existing AI agents (analizador, creador, critico, ensamblador).
- **FR-002**: The pipeline MUST support the "Single-Call Multi-Agent" pattern to save tokens and minimize latency.
- **FR-003**: The pipeline MUST integrate an auditing step utilizing local Nous Hermes 3 for security and logic validation.
- **FR-004**: The system MUST handle Mermaid syntax reconstruction reliably at the end of the pipeline.
- **FR-005**: The pipeline MUST support failover between Gemini and Groq API services.
- **FR-006**: The pipeline MUST implement a format-aware Query Builder to fetch targeted pedagogical context rather than generic vector searches.
- **FR-007**: The pipeline MUST enforce a Grounding threshold via the Critic Agent; if context is insufficient, it MUST fail gracefully with HTTP 422 instead of hallucinating.

### Key Entities

- **PipelinePayload**: The `multipart/form-data` input structure containing the raw binary document (`document_raw`) and required metadata (`profile`, `format`, `nicho_sector`).
- **AgentOutput**: The intermediate output structure generated by each AI agent.
- **AuditReport**: The structure containing the review and findings from the Hermes audit model.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: The end-to-end pipeline processing time from raw input to final assembly must be under 5 seconds on average.
- **SC-002**: Token usage per full pipeline run must not exceed the specified threshold for the "ahorrar tokens" directive.
- **SC-003**: The Hermes auditing step must complete in under 10 seconds locally.
- **SC-004**: The pipeline gracefully handles and recovers from rate-limit errors via failover 100% of the time.

## Assumptions

- We assume Nous Hermes 3 is successfully configured and accessible locally via Ollama.
- We assume the Backend will transmit raw, unparsed binary documents (e.g., PDF) to preserve structural fidelity, overriding earlier assumptions of pre-parsed textual payloads.
- The pipeline will initially process sequential tasks before scaling to concurrent async tasks.
